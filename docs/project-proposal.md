## 2. Главная сущность и справочник

**Главная сущность:** кредитная заявка.

Кредитная заявка представляет собой основную запись процесса. Она содержит информацию о заявке клиента на получение кредитного продукта и проходит несколько этапов обработки.

**Справочник:** кредитный продукт.

Справочник содержит перечень кредитных продуктов, доступных для оформления.

**Поле-ссылка:** `creditProductId`.

Каждая кредитная заявка содержит числовую ссылку на выбранный кредитный продукт.

Пример:

```text
Кредитная заявка
    |
    └── creditProductId → Кредитный продукт
```

### Что здесь нужно сделать

Тебе нужно выбрать **одну главную сущность**, вокруг которой будет строиться вся лабораторная.

В нашей работе это:

> кредитная заявка.

Не нужно делать одновременно главными сущностями клиента, кредита, банка, портфеля и риск-анализа.

Справочник тоже должен быть один основной:

> кредитный продукт.

В заявке хранится его ID:

```text
creditProductId
```

## 3. Роли и права

В системе используются следующие роли.

| Роль                                  | Создаёт заявку | Назначает аналитика | Меняет статус |
| ------------------------------------- | -------------- | ------------------- | ------------- |
| Кредитный менеджер                    | Да             | Да                  | Нет           |
| Кредитный аналитик                    | Нет            | Нет                 | Да            |
| Руководитель кредитного подразделения | Нет            | Нет                 | Нет           |

### Кредитный менеджер

Создаёт кредитные заявки, указывает необходимую информацию и назначает кредитного аналитика для проведения анализа.

### Кредитный аналитик

Работает с назначенными ему кредитными заявками и изменяет их статус в процессе проведения анализа.

### Руководитель кредитного подразделения

Просматривает информацию о заявках и состоянии их обработки.

**Ограничение:** кредитный аналитик может изменять статус только той кредитной заявки, которая назначена ему.

### Что здесь нужно сделать

Здесь тебе нужно показать, что разные пользователи имеют разные права.

Главное правило:

> тот, кто создаёт заявку, не должен быть тем же самым пользователем, который выполняет её анализ.

## 6. Что не входит в семестр

В рамках учебного проекта не реализуются:

1. Автоматическое принятие окончательного решения о выдаче кредита.
2. Реальная проверка кредитной истории клиентов.
3. Подключение к внешним бюро кредитных историй.
4. Реальная банковская система управления кредитным портфелем.
5. Проведение реальных финансовых операций.
6. Выдача денежных средств клиенту.
7. Интеграция с платёжными системами.
8. Мобильное приложение.
9. Полноценная промышленная система банковского скоринга.

### Что здесь нужно сделать

Этот раздел нужен, чтобы **не раздувать проект**.

Мы показываем, что делаем учебную информационную систему, которая управляет процессом работы с кредитными заявками.

Мы **не делаем настоящий банковский скоринг** и не подключаем реальные банковские данные.
