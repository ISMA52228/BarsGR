# API-контракт системы

## 1. Общие сведения

API предназначен для работы с заявками на анализ кредитных рисков в подсистеме управления кредитным портфелем АО «ТБанк».

- Базовый адрес: `/api/v1`
- Формат обмена: JSON.
- Кодировка: UTF-8.
- Для запросов с телом: `Content-Type: application/json`.
- Для получения JSON: `Accept: application/json`.

Все идентификаторы в URL и JSON представлены целыми числами. Даты и время, если они будут добавлены в реализацию, следует передавать в формате ISO 8601.

## 2. Используемые сущности

### CreditRiskRequest

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `id` | integer | В ответе | Идентификатор заявки |
| `number` | string | Да | Уникальный номер заявки |
| `title` | string | Да | Краткое название |
| `description` | string | Нет | Описание кредитного риска |
| `status` | string | Да | Статус заявки |
| `riskTypeId` | integer | Да | Идентификатор типа риска |
| `createdByUserId` | integer | Да | Идентификатор создателя |
| `assigneeUserId` | integer или null | Нет | Идентификатор ответственного сотрудника |

Допустимые значения `status`:

- `NEW` — заявка создана и ещё не назначена;
- `IN_PROGRESS` — заявка находится в работе;
- `DONE` — анализ завершён;
- `REJECTED` — заявка отклонена.

### RiskType

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор типа риска |
| `name` | string | Название типа риска |

### User

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор пользователя |
| `name` | string | Имя пользователя |
| `login` | string | Уникальный логин |

## 3. Методы API

### 3.1. Получение списка заявок

**GET** `/api/v1/credit-risk-requests`

Получает список заявок на анализ кредитных рисков.

Успешный ответ: `200 OK`.

```json
[
  {
    "id": 1,
    "number": "CR-0001",
    "title": "Оценка кредитного риска клиента",
    "description": "Проверка финансовых показателей и кредитной истории",
    "status": "NEW",
    "riskTypeId": 1,
    "createdByUserId": 2,
    "assigneeUserId": null
  }
]
```

Если заявок нет, возвращается пустой массив `[]`.

### 3.2. Получение заявки по идентификатору

**GET** `/api/v1/credit-risk-requests/{id}`

Параметр пути:

| Параметр | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор заявки |

Успешный ответ: `200 OK`.

Пример ответа:

```json
{
  "id": 1,
  "number": "CR-0001",
  "title": "Оценка кредитного риска клиента",
  "description": "Проверка финансовых показателей",
  "status": "NEW",
  "riskTypeId": 1,
  "createdByUserId": 2,
  "assigneeUserId": null
}
```

Если заявка не найдена, возвращается `404 Not Found`.

### 3.3. Создание заявки

**POST** `/api/v1/credit-risk-requests`

Создаёт новую заявку. Идентификатор и уникальный номер назначаются системой.

Тело запроса:

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| `title` | string | Да | Название заявки |
| `description` | string | Нет | Описание |
| `riskTypeId` | integer | Да | Тип риска |
| `createdByUserId` | integer | Да | Создатель заявки |

Пример запроса:

```json
{
  "title": "Оценка риска по кредитному портфелю",
  "description": "Необходимо оценить вероятность просрочки",
  "riskTypeId": 1,
  "createdByUserId": 2
}
```

Успешный ответ: `201 Created`.

В ответе возвращается созданная заявка со статусом `NEW`, назначенным `id` и номером.

### 3.4. Назначение ответственного сотрудника

**PATCH** `/api/v1/credit-risk-requests/{id}/assignee`

Назначает пользователя ответственным за анализ заявки.

Тело запроса:

```json
{
  "assigneeUserId": 3
}
```

Успешный ответ: `200 OK` с обновлённой заявкой.

Если заявка или пользователь не найдены, возвращается `404 Not Found`.

### 3.5. Изменение статуса заявки

**PATCH** `/api/v1/credit-risk-requests/{id}/status`

Изменяет текущий статус заявки.

Тело запроса:

```json
{
  "status": "IN_PROGRESS"
}
```

Допустимые значения: `NEW`, `IN_PROGRESS`, `DONE`, `REJECTED`.

Успешный ответ: `200 OK` с обновлённой заявкой. Если заявка не найдена, возвращается `404 Not Found`. Если передан недопустимый статус, возвращается `400 Bad Request`.

## 4. Коды ответов

| Код | Название | Когда используется |
|---|---|---|
| `200` | OK | Запрос выполнен успешно |
| `201` | Created | Заявка успешно создана |
| `400` | Bad Request | Некорректные данные или недопустимый статус |
| `404` | Not Found | Заявка или связанный пользователь/тип риска не найдены |
| `409` | Conflict | Конфликт уникальности, например повторяющийся номер |
| `500` | Internal Server Error | Непредвиденная ошибка сервера |

Пример ответа при ошибке валидации:

```json
{
  "message": "Передан недопустимый статус заявки",
  "status": 400
}
```

## 5. Связь API с моделью данных

Методы API работают с сущностью `CreditRiskRequest`. Поля `riskTypeId`, `createdByUserId` и `assigneeUserId` ссылаются на записи справочников `RiskType` и `User`. Это соответствует ER-модели из файла `data-model.md).

| Операция | Метод и путь | Основные поля |
|---|---|---|
| Получить все заявки | GET `/api/v1/credit-risk-requests` | Все поля заявки |
| Получить одну заявку | GET `/api/v1/credit-risk-requests/{id}` | `id` |
| Создать заявку | POST `/api/v1/credit-risk-requests` | `title`, `description`, `riskTypeId`, `createdByUserId` |
| Назначить исполнителя | PATCH `/api/v1/credit-risk-requests/{id}/assignee` | `assigneeUserId` |
| Изменить статус | PATCH `/api/v1/credit-risk-requests/{id}/status` | `status` |

## 6. Примечание по реализации

Документ описывает согласованный проектный контракт API. Он фиксирует ожидаемые URL, поля и форматы обмена, но сам по себе не означает, что все перечисленные HTTP-обработчики уже реализованы на сервере. При реализации ASP.NET Core маршруты и DTO следует привести в соответствие с этим документом.
