# API-контракт системы

## 1. Общие сведения

API предназначен для работы с кредитными заявками в подсистеме управления кредитным портфелем АО «ТБанк».

- Базовый адрес: `/api/v1`
- Формат обмена: JSON.
- Кодировка: UTF-8.
- Для запросов с телом: `Content-Type: application/json`.
- Для получения JSON: `Accept: application/json`.

## 2. Модель данных

### CreditRiskRequest

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Машинный идентификатор |
| `number` | string | Уникальный номер заявки |
| `title` | string | Заголовок, 5–80 символов |
| `creditProductId` | integer | Ссылка на кредитный продукт |
| `description` | string | Описание, 10–500 символов |
| `status` | string | Текущий статус |
| `createdByUserId` | integer | Пользователь, создавший заявку |
| `assigneeId` | integer или null | Назначенный кредитный аналитик |

Допустимые значения `status`: `New`, `InProgress`, `Closed`, `Cancelled`.

### CreditProduct

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор кредитного продукта |
| `name` | string | Название продукта |

### User

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | Идентификатор пользователя |
| `name` | string | Имя пользователя |
| `login` | string | Уникальный логин |

## 3. Методы API

### 3.1. Получение списка заявок

**GET** `/api/v1/credit-risk-requests`

Успешный ответ: `200 OK`. Если заявок нет, возвращается пустой массив `[]`.

```json
[
  {
    "id": 1,
    "number": "CR-2026-001",
    "title": "Заявка на потребительский кредит",
    "creditProductId": 1,
    "description": "Анализ заявки на потребительский кредит",
    "status": "New",
    "createdByUserId": 2,
    "assigneeId": null
  }
]
```

### 3.2. Получение заявки по идентификатору

**GET** `/api/v1/credit-risk-requests/{id}`

Параметр пути `id` — целочисленный идентификатор заявки.

Успешный ответ: `200 OK` с объектом `CreditRiskRequest`. Если запись не найдена, возвращается `404 Not Found`.

### 3.3. Создание заявки

**POST** `/api/v1/credit-risk-requests`

Тело запроса:

| Поле | Тип | Обязательность |
|---|---|---|
| `title` | string | Да |
| `creditProductId` | integer | Да |
| `description` | string | Да |

Пример:

```json
{
  "title": "Заявка на потребительский кредит",
  "creditProductId": 1,
  "description": "Анализ заявки на потребительский кредит"
}
```

Сервер проверяет данные, определяет создателя по текущей учётной записи, присваивает `id` и `number`, устанавливает статус `New`. Исполнитель при создании не назначается.

Успешный ответ: `201 Created` с созданной заявкой. При некорректных данных возвращается `400 Bad Request`.

### 3.4. Назначение кредитного аналитика

**PATCH** `/api/v1/credit-risk-requests/{id}/assignee`

Назначает аналитика отдельным действием, не изменяя статус заявки.

Тело запроса:

```json
{
  "assigneeId": 3
}
```

Успешный ответ: `200 OK` с обновлённой заявкой. Если заявка или пользователь не найдены, возвращается `404 Not Found`.

### 3.5. Изменение статуса заявки

**PATCH** `/api/v1/credit-risk-requests/{id}/status`

Тело запроса:

```json
{
  "status": "InProgress"
}
```

Допустимые значения: `New`, `InProgress`, `Closed`, `Cancelled`.

Успешный ответ: `200 OK` с обновлённой заявкой. Если заявка не найдена, возвращается `404 Not Found`. Если передан неизвестный статус или переход запрещён, возвращается `400 Bad Request` или `409 Conflict`.

## 4. Коды ответов

| Код | Название | Когда используется |
|---|---|---|
| `200` | OK | Запрос выполнен успешно |
| `201` | Created | Заявка создана |
| `400` | Bad Request | Некорректные поля или неизвестный статус |
| `404` | Not Found | Заявка, пользователь или продукт не найдены |
| `409` | Conflict | Конфликт состояния или уникальности |
| `500` | Internal Server Error | Непредвиденная ошибка сервера |

Пример ошибки:

```json
{
  "message": "Передан недопустимый статус заявки",
  "status": 400
}
```

## 5. Связь API с моделью данных

| Операция | Метод и путь | Основные поля |
|---|---|---|
| Получить список | GET `/api/v1/credit-risk-requests` | Все поля заявки |
| Получить одну заявку | GET `/api/v1/credit-risk-requests/{id}` | `id` |
| Создать заявку | POST `/api/v1/credit-risk-requests` | `title`, `creditProductId`, `description` |
| Назначить аналитика | PATCH `/api/v1/credit-risk-requests/{id}/assignee` | `assigneeId` |
| Изменить статус | PATCH `/api/v1/credit-risk-requests/{id}/status` | `status` |

Поля `creditProductId`, `createdByUserId` и `assigneeId` связывают заявку с таблицами `CreditProduct` и `User`. Имена полей и коды статусов согласованы с требованиями ЛР1.

## 6. Примечание по реализации

Документ описывает проектный контракт API. Он фиксирует ожидаемые URL, поля и форматы обмена, но не означает, что HTTP-обработчики уже реализованы на сервере. При разработке ASP.NET Core маршруты и DTO должны соответствовать этому документу.
